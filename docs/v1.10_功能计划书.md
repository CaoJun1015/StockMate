## 一、优化目标

在不改变核心业务逻辑的前提下，提升**个人日常使用**的效率和安全感。

---

## 二、6项功能详细设计

### 2.1 自动备份（启动时）

**现状**：`backup_database()` 已实现，但需手动调用或通过"数据工具"菜单点击。

**方案**：`init_db()` 末尾调用 `backup_database()`，每次启动自动备份。

**改动点**：
- `database.py`：`init_db()` 函数末尾加一行 `backup_database()`
- 不在 UI 层做，因为 `init_db()` 是每次启动必经之路

**风险**：极低。`backup_database()` 已有异常处理，失败不影响主流程。

---

### 2.2 数据库损坏恢复

**现状**：无检测。SQLite 异常退出可能导致文件损坏，再次打开时行为不可预测。

**方案**：`init_db()` 建表后执行 `PRAGMA integrity_check`，若失败则提示用户并从最近备份恢复。

**改动点**：
- `database.py`：`init_db()` 加 `integrity_check` + 自动恢复逻辑
- `main.py`：`init_db()` 返回值改为 `(bool, str)`，UI 层根据返回值决定是否弹窗

**恢复策略**：
1. 检测到损坏 → 弹窗告知用户
2. 自动查找 `backups/` 下最新备份
3. 用备份替换损坏的数据库文件
4. 重新执行 `init_db()`
5. 告知用户：数据已恢复到最近备份的时间点

**风险**：低。仅在启动时执行一次，不影响正常使用。

---

### 2.3 模糊搜索

**现状**：数据库层已使用 `LIKE %keyword%`（模糊搜索），但搜索范围有限（只搜 series/cpu/note）。

**方案**：扩展搜索范围，让用户输入任意关键词都能搜到。

**改动点**：
- `search_products`：增加 `ram`、`storage`、`gpu`、`screen` 字段到 LIKE 条件
- `search_customers`：增加 `wechat`、`qq`、`phone`、`note` 字段
- `search_suppliers`：增加 `wechat`、`qq`、`phone`、`note` 字段
- `search_quotes`：已支持客户名模糊搜索，无需改动

**风险**：极低。只是扩展 SQL WHERE 条件。

---

### 2.4 表格排序

**现状**：所有 `QTableWidget` 不支持点击列头排序。

**方案**：每个 `QTableWidget` 创建后加一行 `setSortingEnabled(True)`。

**改动点**（约 10 处表格）：
- 机型管理表格
- 库存批次表格
- 客户列表表格
- 上游管理表格
- 报价记录表格
- 收付款记录表格
- 其他弹出对话框中的表格

**风险**：极低。PyQt6 内置功能，不影响数据。

---

### 2.5 操作记录展示

**现状**：`add_operation_log()` 和 `get_operation_logs()` 已实现，但 UI 无入口。

**方案**：在"数据工具"菜单或主界面加一个"操作日志"按钮，弹出对话框展示最近 50 条记录。

**改动点**：
- `main.py`：新增 `OperationLogDialog` 类（一个简单的 QDialog + QTableWidget）
- 菜单栏或工具栏新增"操作日志"入口

**风险**：极低。纯展示，不修改数据。

---

### 2.6 收款提醒

**现状**：出库后无提醒机制，用户需要手动翻列表找未收款的订单。

**方案**：报价管理表格中，已出库且超过 N 天未收款的订单**红色高亮**显示。

**判断逻辑**：
- `status = '已出库'` 且 `received_amount < 总额`
- 出库日期距今天 > 7 天（可配置）

**改动点**：
- `main.py`：`refresh_records()` 中，遍历已出库报价行，计算天数，超期行设置红色前景色
- 可选：添加一个"到期天数"列

**风险**：低。纯 UI 展示逻辑，不改数据。
