## 二、详细方案

### OPT-001：状态机守卫

**问题描述**

`update_quote_status()` 函数没有校验状态流转的合法性，允许任意跳转。例如可以从"已收款"直接改为"待确认"，或从"待确认"跳到"已收款"。

**当前代码**

```python
def update_quote_status(quote_id, new_status):
    # 直接更新，无校验
    conn.execute("UPDATE quotes SET status=? WHERE id=?", (new_status, quote_id))
```

**影响**

- 数据可能进入非法状态
- UI层虽有部分校验，但绕过UI直接调用函数时无保护

**修复方案**

定义合法状态流转表，更新前校验：

```python
# 合法状态流转表
VALID_TRANSITIONS = {
    "待确认": ["已报价", "已取消"],
    "已报价": ["已出库", "已取消"],
    "已出库": ["已收款", "已取消"],
    "已收款": [],           # 已收款不可改
    "已取消": [],           # 已取消不可改
}

def update_quote_status(quote_id, new_status):
    conn = get_connection()
    try:
        row = conn.execute(
            "SELECT status, batch_id, quote_quantity FROM quotes WHERE id=?",
            (quote_id,)
        ).fetchone()
        if not row:
            return False, "报价记录不存在"

        old_status = row[0]
        batch_id = row[1]
        quote_quantity = row[2] or 0

        # 校验状态流转合法性
        if new_status not in VALID_TRANSITIONS.get(old_status, []):
            return False, f"不允许从「{old_status}」变更为「{new_status}」"

        # 执行状态变更（保留原有业务逻辑）
        if old_status == "已出库" and new_status == "已取消":
            conn.execute(
                "UPDATE batches SET remaining = remaining + ? WHERE id = ?",
                (quote_quantity, batch_id)
            )
            conn.execute(
                "UPDATE quotes SET sn_list = '' WHERE id = ?",
                (quote_id,)
            )

        conn.execute("UPDATE quotes SET status=? WHERE id=?", (new_status, quote_id))
        conn.commit()
        return True, "状态更新成功"
    except Exception as e:
        conn.rollback()
        raise e
    finally:
        conn.close()
```

**测试用例**

```python
def test_status_guard_rejects_invalid_transition(sample_quote):
    """从已收款跳到待确认应该被拒绝"""
    # 先设为已收款
    db.update_quote_status(sample_quote, "已报价")
    db.update_quote_status(sample_quote, "已出库")
    db.add_payment(quote_id=sample_quote, ...)
    # 尝试非法跳转
    success, msg = db.update_quote_status(sample_quote, "待确认")
    assert not success
    assert "不允许" in msg
```

### OPT-002：出库逻辑封装

**问题描述**

出库操作在 `main.py` 的 `on_ship_quote()` 方法中直接用SQL实现，包括扣减库存、更新状态、保存SN。这些逻辑没有封装在 `database.py` 中。

**当前代码位置**

`src/main.py` 第1266-1320行

**影响**

- 出库逻辑无法被单元测试
- 如果其他功能需要出库（批量出库、API调用），必须复制代码
- 出库时没有校验SN数量是否等于 `quote_quantity`
- 事务管理分散在UI层

**修复方案**

在 `database.py` 中新增 `ship_quote()` 函数：

```python
def ship_quote(quote_id, sn_list=""):
    """
    出库操作（封装完整业务逻辑）
    
    1. 校验报价状态（只有待确认/已报价可出库）
    2. 校验库存充足
    3. 扣减批次库存
    4. 保存出库SN到报价记录
    5. 更新状态为"已出库"
    
    Returns:
        (success: bool, message: str)
    """
    conn = get_connection()
    try:
        # 1. 获取报价信息
        quote = conn.execute(
            "SELECT status, batch_id, quote_quantity FROM quotes WHERE id=?",
            (quote_id,)
        ).fetchone()
        if not quote:
            return False, "报价记录不存在"

        if quote["status"] not in ("待确认", "已报价"):
            return False, f"当前状态「{quote['status']}」不允许出库"

        batch_id = quote["batch_id"]
        quote_quantity = quote["quote_quantity"] or 1

        # 2. 校验库存
        batch = conn.execute(
            "SELECT remaining FROM batches WHERE id=?",
            (batch_id,)
        ).fetchone()
        if not batch:
            return False, "批次不存在"

        if batch["remaining"] < quote_quantity:
            return False, f"库存不足！当前剩余 {batch['remaining']} 台，需要 {quote_quantity} 台"

        # 3. 扣减库存
        conn.execute(
            "UPDATE batches SET remaining = remaining - ? WHERE id = ?",
            (quote_quantity, batch_id)
        )

        # 4. 更新报价状态和SN
        conn.execute(
            "UPDATE quotes SET status='已出库', sn_list=? WHERE id=?",
            (sn_list, quote_id)
        )

        conn.commit()
        return True, "出库成功"
    except Exception as e:
        conn.rollback()
        return False, f"出库失败: {str(e)}"
    finally:
        conn.close()
```

**UI层调用方式**

```python
def on_ship_quote(self):
    # ... 获取 quote_id, sn_list ...
    success, msg = db.ship_quote(quote_id, sn_list)
    if success:
        QMessageBox.information(self, "成功", msg)
    else:
        QMessageBox.warning(self, "出库失败", msg)
    self.refresh_records()
```

**测试用例**

```python

    """正常出库成功"""
    success, msg = db.ship_quote(sample_quote, "SN001,SN002")
    assert success
    quote = db.get_quote_by_id(sample_quote)
    assert quote["status"] == "已出库"
    assert quote["sn_list"] == "SN001,SN002"

    """库存不足时出库失败"""

    success, msg = db.ship_quote(sample_quote, "SN001,SN002,SN003,SN004,SN005,SN006")
    assert not success
    assert "库存不足" in msg

def test_ship_quote_wrong_status(sample_quote):
    """已出库状态不能再次出库"""
    db.ship_quote(sample_quote, "SN001")
    success, msg = db.ship_quote(sample_quote, "SN003")
    assert not success
    assert "不允许出库" in msg
```

### OPT-003：状态回退考虑原状态

**问题描述**

`_update_quote_payment_status()` 函数在收款删除/减少后同步状态时，只根据 `sn_list` 判断回退到哪个状态：

```python
if new_received >= total_amount:
    new_status = "已收款"
elif sn_list:
    new_status = "已出库"
else:
    new_status = "待确认"  # ← 问题在这里
```

如果原来是"已报价"状态（还没出库），客户付了部分款又退款，状态会变成"待确认"而不是"已报价"。

**修复方案**

查询原始状态，回退时保留原状态：

```python
def _update_quote_payment_status(conn, quote_id):
    row = conn.execute(
        "SELECT received_amount, quote_price, quote_quantity, status, sn_list FROM quotes WHERE id=?",
        (quote_id,),
    ).fetchone()
    if not row:
        return

    total_amount = row["quote_price"] * row["quote_quantity"]
    new_received = row["received_amount"]
    current_status = row["status"]
    sn_list = row["sn_list"] or ""

    # 计算 paid
    paid = "是" if new_received >= total_amount else "否"

    # 计算 status
    if new_received >= total_amount:
        new_status = "已收款"
    elif current_status == "已收款":
        # 从已收款回退，根据SN判断
        new_status = "已出库" if sn_list else "待确认"
    else:
        # 未收满，保持当前状态不变
        new_status = current_status

    conn.execute(
        "UPDATE quotes SET paid=?, status=? WHERE id=?",
        (paid, new_status, quote_id),
    )
```

**测试用例**

```python
def test_partial_payment_delete_rollback_to_quoted(sample_quote):
    """已报价→部分收款→删除收款，应回退到已报价"""
    # 设为已报价
    db.update_quote_status(sample_quote, "已报价")
    
    # 部分收款
    payment_id = db.add_payment(quote_id=sample_quote, amount=1000, ...)
    
    # 删除收款
    db.delete_payment(payment_id)
    
    # 应回退到已报价，不是待确认
    quote = db.get_quote_by_id(sample_quote)
    assert quote["status"] == "已报价"
```

### OPT-004：清理调试代码

**问题描述**

`_update_quote_payment_status()` 中有调试残留：

```python
if current_status != new_status or True:  # paid 总是需要更新
```

`or True` 导致每次都执行UPDATE，即使状态没有变化。

**修复方案**

分开更新 `paid` 和 `status`，或只在需要时更新：

```python
# 方案A：分开更新
conn.execute("UPDATE quotes SET paid=? WHERE id=?", (paid, quote_id))
if current_status != new_status:
    conn.execute("UPDATE quotes SET status=? WHERE id=?", (new_status, quote_id))

# 方案B：合并更新，去掉 or True
if current_status != new_status or current_paid != paid:
    conn.execute(
        "UPDATE quotes SET paid=?, status=? WHERE id=?",
        (paid, new_status, quote_id),
    )
```

### OPT-005：软删除机制

**问题描述**

`delete_batch`、`delete_customer`、`delete_supplier`、`delete_quote` 全部是硬删除，财务历史会丢失。

**影响**

- 审计时查不到已删除的记录
- 误删后无法恢复
- 财务对账可能出现差异

**修复方案**

**阶段一：新增字段**

```sql
ALTER TABLE quotes ADD COLUMN is_deleted INTEGER DEFAULT 0;
ALTER TABLE batches ADD COLUMN is_deleted INTEGER DEFAULT 0;
ALTER TABLE customers ADD COLUMN is_deleted INTEGER DEFAULT 0;
ALTER TABLE suppliers ADD COLUMN is_deleted INTEGER DEFAULT 0;
ALTER TABLE payments ADD COLUMN is_deleted INTEGER DEFAULT 0;
```

**阶段二：修改删除函数**

```python
def delete_quote(quote_id):
    """软删除报价记录"""
    conn = get_connection()
    try:
        # 获取报价信息，判断是否需要回补库存
        row = conn.execute(
            "SELECT status, batch_id, quote_quantity FROM quotes WHERE id=?",
            (quote_id,)
        ).fetchone()

        if row and row[0] == "已出库":
            batch_id = row[1]
            quote_quantity = row[2] or 0
            conn.execute(
                "UPDATE batches SET remaining = remaining + ? WHERE id = ?",
                (quote_quantity, batch_id)
            )

        # 软删除：标记 is_deleted
        conn.execute(
            "UPDATE quotes SET is_deleted=1, status='已取消' WHERE id=?",
            (quote_id,)
        )
        # 关联的付款记录也标记删除
        conn.execute(
            "UPDATE payments SET is_deleted=1 WHERE quote_id=?",
            (quote_id,)
        )
        conn.commit()
    except Exception as e:
        conn.rollback()
        raise e
    finally:
        conn.close()
```

**阶段三：修改查询函数**

所有查询加上 `WHERE is_deleted=0` 或 `WHERE is_deleted IS NULL`：

```python
def get_quote_by_id(quote_id):
    conn = get_connection()
    row = conn.execute(
        "SELECT * FROM quotes WHERE id=? AND (is_deleted=0 OR is_deleted IS NULL)",
        (quote_id,)
    ).fetchone()
    conn.close()
    return dict(row) if row else None
```

**注意**

软删除改动较大，建议作为独立版本迭代，不要和P0修复混在一起。

### OPT-007：外键约束管理

**问题描述**

`delete_batch` 中临时关闭外键约束：

```python
conn.execute("PRAGMA foreign_keys = OFF")
# ... 手动级联删除 ...
conn.execute("PRAGMA foreign_keys = ON")
```

如果中间抛异常，外键约束可能一直处于关闭状态。

**修复方案**

在事务中操作，利用SQLite的 `ON DELETE CASCADE`：

```python
def delete_batch(batch_id):
    conn = get_connection()
    try:
        # 查询批次信息，用于回滚供应商欠款
        row = conn.execute(
            "SELECT supplier_id, purchase_price, quantity FROM batches WHERE id=?",
            (batch_id,)
        ).fetchone()

        # 回滚供应商欠款
        if row and row[0]:
            total = row[1] * row[2]
            conn.execute(
                "UPDATE suppliers SET balance = balance - ? WHERE id=?",
                (total, row[0])
            )

        # 依赖 ON DELETE CASCADE 自动级联删除
        conn.execute("DELETE FROM batches WHERE id=?", (batch_id,))
        conn.commit()
    except Exception as e:
        conn.rollback()
        raise e
    finally:
        conn.close()
```

**前提**：建表时需要设置 `ON DELETE CASCADE`：

```sql
CREATE TABLE quotes (
    ...
    FOREIGN KEY (batch_id) REFERENCES batches(id) ON DELETE CASCADE,
    ...
);

CREATE TABLE payments (
    ...
    FOREIGN KEY (quote_id) REFERENCES quotes(id) ON DELETE CASCADE,
    ...
);
```

### OPT-008：连接复用（可选）

**问题描述**

每次数据库操作都创建新连接。

**影响**

- 桌面单用户应用影响不大
- 批量操作（如导入Word价格表）时可能较慢

**修复方案**

使用连接池或模块级单例连接：

```python
# 方案A：模块级连接（简单）
_conn = None

def get_connection():
    global _conn
    if _conn is None:
        os.makedirs(APP_DATA_DIR, exist_ok=True)
        _conn = sqlite3.connect(DB_PATH, check_same_thread=False)
        _conn.row_factory = sqlite3.Row
        _conn.execute("PRAGMA journal_mode=WAL")
        _conn.execute("PRAGMA foreign_keys=ON")
    return _conn

def close_connection():
    global _conn
    if _conn:
        _conn.close()
        _conn = None
```

**注意**

SQLite单写多读，连接复用需要注意线程安全。桌面应用通常单线程，问题不大。

### NEW-001：get_customer_stats 返回 None

**问题描述**

当客户没有任何报价记录时，`get_customer_stats` 的 `total_amount` 和 `total_profit` 返回 `None` 而不是 `0`。

**根因**

SQL的 `SUM()` 在没有匹配行时返回 NULL，Python转为None。

**修复方案**

使用 `COALESCE`：

```python
def get_customer_stats(customer_id):
    conn = get_connection()
    row = conn.execute(
        """SELECT 
            COUNT(*) as total_orders,
            COALESCE(SUM(q.quote_price * q.quote_quantity), 0) as total_amount,
            COALESCE(SUM((q.quote_price - b.purchase_price) * q.quote_quantity), 0) as total_profit
        FROM quotes q
        JOIN batches b ON q.batch_id = b.id
        WHERE q.customer_id = ? AND q.status != '已取消'""",
        (customer_id,)
    ).fetchone()
    conn.close()
    return dict(row) if row else None
```

### 当前状态流转图

```
待确认 ──→ 已报价 ──→ 已出库 ──→ 已收款
  │          │          │
  └──────────┴──────────┘
           已取消
```

### 合法状态流转表

| 当前状态 | 允许变更到 |
|----------|-----------|
| 待确认 | 已报价、已取消 |
| 已报价 | 已出库、已取消 |
| 已出库 | 已收款、已取消 |
| 已收款 | （不可变更） |
| 已取消 | （不可变更） |

### 数据库表关系

```
products (1) ───< batches (N) ───< quotes (N)
                     │                │
                     ▼                ▼
                suppliers         customers
                     │                │
                     ▼                ▼
                suppliers.balance  quotes.received_amount
                     │                │
                     └──────┬─────────┘
                            ▼
                      payments (收付款流水)
```
