# 架构收敛与完整恢复说明

2026-09-09，本轮本地交付，应用版本与 schema v6 不变，尚未发布。

## 删除保护

财务启用后，任何有关联批次的机型均不能删除，含零库存和已软删除的历史批次；无任何批次的纯目录机型仍可删除。批次也不能删除。

财务启用前，已报价、已出库、已收款记录阻止删除。删除机型先检查全部关联批次，任一拒绝则机型、批次、报价和余额均不变。合法删除沿用软删除与审计。

## 实际月报

- 收入、成本、毛利和机型利润排行与财务账本共用查询，按凭证业务日期归月。未出库报价不计收入，跨批次采用实际记账成本；12,000 元收入减 9,200 元成本，毛利为 2,800 元。
- 退货在退货发生月冲减收入；回库退货冲回成本，不回库退货保留原成本处理。实际毛利不含报价页面税务估算，报价页面估算功能仍保留。
- “本月出库订单数”取出库快照数量；机型净销售数量为当月出库减当月退货，可为负数。
- “当月客户净收款”为实际客户收款减现金退款，含历史订单回款和预收，冲销按其凭证日期计入。期初、内部转账和非现金调整不计入，已移除回款率。
- 财务启用前月份显示“无完整账本数据”，启用当月标明统计起始日。月份不完整或上月基数不大于零时，环比显示“不可比”。
- 滞销提示使用当前库存和所选月实际出库活动，不代表历史月末库存；未成交报价不再影响判断。

## 恢复操作

1. 保存好需要保留的新业务信息。选择“JSON 备份恢复”或“数据安全 → SQLite 备份恢复…”。两者都将完整替换当前数据，不支持跨库合并。
2. 选择备份。程序在临时库中导入/复制、升级，并检查 SQLite 完整性、外键及业务对账。当前数据库此时不变。
3. 预检成功后查看备份路径、记录数量与完整替换提示。取消则不替换；确认后自动创建并验证当前数据库安全备份。
4. 程序替换后再次检查。成功显示安全备份位置并退出，请重新启动；恢复期间业务界面暂停写入。
5. 失败时阅读明细：预检或安全备份失败不替换；替换失败自动还原安全备份，并明确报告回滚结果与备份位置。如果回滚也失败，请保留相关文件并按提示从安全备份恢复，不继续录入业务。

对账异常会阻止替换，没有强行恢复选项。旧版转换只沿用现有支持格式，不猜测缺失历史。旧 JSON 若未包含操作日志或价格快照，无法恢复这些未备份内容；新导出已包含它们。JSON 底层导入仅允许隔离空库，不能追加到正式库。重复恢复不会累加数据。
