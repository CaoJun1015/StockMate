## OPT-001 · JSON 完整恢复边界

**优先级：P1｜状态：已实现，待提交**

业务决定：取消合并导入；JSON 仅完整替换。隔离空库导入保留原记录 ID、事件键与关联，重复恢复不累加。损坏、高版本、缺失必要关联或对账异常均阻止替换。

验证：非空目标替换、重复恢复、旧版转换、异常保留当前库、恢复后收款冲销均有回归测试。跨库合并不属于已完成功能。

## OPT-002 · 统一完整恢复流程

**优先级：P1｜状态：已实现，待提交**

JSON 与 SQLite 共用服务协调：隔离预检及升级 → 对账 → 展示影响并确认 → 验证安全备份 → 替换并复检 → 成功退出。替换失败自动回滚，失败信息包含安全备份位置；对账异常没有强行恢复入口。

验证：覆盖 v5/v6、非空目标、重复恢复、安全备份失败、替换失败回滚和界面确认/取消。旧 JSON 未导出的日志及价格快照无法凭空恢复。

## OPT-003 · 建立自动化发布检查

**优先级：P1｜类型：工程质量｜状态：待开始**

问题：v1.17 发布构建曾因外部 Poppler 的同名 ICU DLL 混入而无法启动，已通过隔离构建搜索路径修复，需要把验证固化。

范围：提供可重复执行的发布检查流程，串联测试、隔离打包、依赖检查、EXE 启动验证、文件哈希与 Release 附件校验。

验收标准：
- 任一测试、打包或启动检查失败时，停止公开 Release。
- 在含外部 DLL 工具目录的环境中构建，产物不混入该目录的冲突库。
- EXE 使用临时数据库启动并验证 schema 与完整性，不读取正式业务数据库。
- 只清理本次验证创建的进程，正确关闭数据库句柄。
- 发布标签、源码提交和附件一致，记录 SHA-256；上传失败可安全重试。
- 文档明确执行命令、凭据要求和失败处理，不记录凭据内容。

涉及位置：build.spec、scripts/，以及后续发布流程配置。

## OPT-004 · 历史异常核对与修复入口

**优先级：P1｜类型：数据治理｜状态：待开始**

目标：将对账异常转化为可定位、可核对、可追溯的处理流程。

范围：展示重复 SN、缺失退货分配、库存流水差异的原始证据；支持定位订单和批次；对可确认的问题提供修复预览和审计记录。无法推断的历史分配保留人工核对入口。

验收标准：
- 每项异常包含关联订单、批次、差异和下一步处理说明。
- 不凭空猜测缺失分配，不静默覆盖历史凭证。
- 修复前自动备份并展示库存与金额变化，用户确认后才应用。
- 修复操作具备事务保护和审计记录；执行后重新对账。
- 对不可自动修复的问题支持导出清单，不把未处理异常标为通过。

涉及位置：src/services/reconciliation_service.py、src/models/finance_queries.py、src/ui/finance_tab.py。

## OPT-005 · 优化出库连续扫码与分配

**优先级：P2｜类型：操作体验｜状态：待开始**

目标：减少扫码、选批次和数量核对的重复操作。

范围：连续扫码、回车不提交；按 SN 自动匹配可用批次；实时显示已分配和待分配数量；来源不完整或多义时提供人工选择。

验收标准：
- 连续扫码及粘贴多行 SN 均可使用，扫描回车不会误提交出库。
- 自动匹配仅在来源唯一且库存可用时生效。
- 重复、已出库、其他机型 SN 给出明确提示。
- 修改或移除 SN 后同步更新批次数量及分配合计。
- 库存不足和数量不一致无法提交；服务层原有校验继续生效。

涉及位置：src/ui/dialogs.py、src/utils/shipment_flow.py、src/services/inventory_service.py。

## OPT-006 · 优化退货选择与提交预览

**优先级：P2｜类型：操作体验｜状态：待开始**

目标：在填写时就减少数量和 SN 错误，并让用户看懂提交结果。

范围：显示订单净可退数量和原分配剩余可退数量；排除已退 SN；提交前预览回库批次、成本冲回、应收变化及实际现金退款。

验收标准：
- 不回库退货也即时减少界面上的可退数量。
- 自动匹配 SN 不选择已经退货的记录，重新扫码不会残留上次分配。
- 部分退货、跨批次退货、重复扫码及不回库场景均有界面测试。
- 预览与服务实际写入结果一致，区分客户余额与现金退款。
- 提交失败不产生部分库存或账务变动，并显示可理解的原因。

涉及位置：src/ui/finance_dialogs.py、src/ui/record_tab.py、src/services/return_service.py。

## OPT-007 · SN 全生命周期查询

**优先级：P2｜类型：查询能力｜状态：待开始**

目标：通过一个 SN 定位设备的库存归属、交易历史与售后过程。

范围：统一查询入口，按时间展示入库、出库、退货和再售事件，链接原订单及批次；明确历史缺失信息。

验收标准：
- 支持完整 SN 查询，显示批次、客户、事件日期和关联单据。
- 同一 SN 多次退售后仍能正确区分各次出库与对应退货。
- 当前状态与库存、退货分配一致；异常或信息不足时不武断显示「在库」。
- 历史没有 SN 的采购退货等事件不伪造关联。
- 无结果与异常重复结果有明确提示，查询不修改业务数据。

涉及位置：src/models/inventory_repository.py、src/models/queries.py、src/ui/。
